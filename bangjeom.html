      기기

      기기 이름은 어느 쪽에서 고쳤는지 표시하는 데만 씁니다.

      「시작」을 누르면 단축어 할일시작에 이 숫자를 넘깁니다. 「조금 했다」와 「끝냈다」는 단축어 할일끝에 할 일 제목을 넘깁니다. 두 단축어는 단축어 앱에 그 이름으로 만들어 두세요.

      훑기에서 밀린 횟수입니다. 자꾸 지는 항목은 게으름이 아니라 잘못 적힌 항목일 때가 많습니다. 숫자가 신경 쓰이면 꺼두세요.

      링크

      할 일 뒤에 링크를 띄어 적으면 링크는 떼어 두고 제목만 남습니다. 실행 화면에서 제목을 누르면 그 링크가 열립니다.

      things:///show?id=… · x-devonthink-item://… · shortcuts://run-shortcut?name=… · x-scrivener-item:///… 처럼 앱이 받는 주소면 무엇이든 됩니다.

      동기화

      Supabase 프로젝트의 주소와 anon 키를 넣으면 맥북과 아이폰이 같은 목록을 봅니다. 한쪽에서 고치면 다른 쪽에 바로 옵니다.

      끝낸 일은 같은 프로젝트의 bangjeom_inbox 표에도 한 줄씩 보냅니다. 쪽글에 같은 주소와 키를 넣어 두면 쪽글이 그날 노트에 가져갑니다. 못 보낸 것은 다음에 연결될 때 다시 보냅니다.

      어느 쪽이 최신인지는 기기 시계가 아니라 서버 문서의 판번호로 가립니다. 기기끼리 시각이 어긋나도 판정이 뒤집히지 않습니다. 양쪽에 서로 다른 변경이 있으면 어느 쪽을 살릴지 묻고, 버리는 쪽은 백업에 남겨 「직전으로 되돌리기」로 살릴 수 있습니다.

      표 만들기

      Supabase의 SQL Editor에 한 번만 붙여넣고 실행하면 됩니다.

      create table if not exists bangjeom (
  id text primary key,
  data jsonb not null,
  device text,
  updated_at timestamptz not null default now()
);

alter table bangjeom enable row level security;

create policy "anon read"  on bangjeom for select using (true);
create policy "anon write" on bangjeom for insert with check (true);
create policy "anon edit"  on bangjeom for update using (true) with check (true);

alter publication supabase_realtime add table bangjeom;

-- 쪽글로 보내는 편지함
create table if not exists bangjeom_inbox (
  id text primary key,
  at bigint not null,
  text text not null,
  device text,
  created_at timestamptz not null default now()
);

alter table bangjeom_inbox enable row level security;

create policy "anon read"  on bangjeom_inbox for select using (true);
create policy "anon write" on bangjeom_inbox for insert with check (true);
create policy "anon edit"  on bangjeom_inbox for update using (true) with check (true);

      규칙

      맨 위 항목에 점을 찍고, 아래로 내려가며 “이걸 더 하고 싶은가”를 묻습니다. 그렇다면 점을 찍고 그 항목이 새 기준이 됩니다. 끝까지 가면 마지막에 점 찍은 것부터 합니다. 하나를 끝내면 방금 한 자리 이후만 다시 훑습니다. 다 못 해도 됩니다. 조금이라도 했으면 끝에 다시 적습니다.
